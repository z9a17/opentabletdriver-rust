# OpenTabletDriver Rust port status

The long-term goal is broader OpenTabletDriver functionality with efficient native Rust report processing. The [original implementation plan](IMPLEMENTATION_PLAN.md) describes the first PTH-660 milestone; its exclusions are historical milestone boundaries, not the final project scope.

The [full parity roadmap](FULL_PARITY_PLAN.md) defines the target against OpenTabletDriver v0.6.7, with [65 scoped tasks](parity/WORK_ITEMS.md), a [capability/source matrix](parity/CAPABILITY_MATRIX.md), a reproducible upstream inventory, an [evidence ledger](parity/EVIDENCE_LEDGER.md) and [GitHub tracking](parity/GITHUB_TRACKING.md).

Release 0.5.0 redesigned the control panel, 0.6.0 added tray behavior, and 0.7.0 improved report-thread scheduling and hover/tip handling; see [input latency](INPUT_LATENCY.md). Release 0.7.1 added behavior contracts and nine golden traces without changing pen handling, mapping, clicks or filtering. Release 0.7.2 added validation bookkeeping and CI checks without changing driver behavior. Release 0.7.3 runs unchanged synchronous .NET Pixels/PostTransform position filters after absolute mapping; the original RadialFollow screen-space class passes an integration replay. Release 0.7.4 shows .NET plugin names, property labels, units and tooltips from unchanged DLL metadata in the Windows Filters editor. Release 0.7.5 moves report decoding, mapping, filtering and the device-session loop into the portable `otd-core` crate without changing driver behavior; CI builds and tests that crate on Linux. Release 0.7.6 adds repeatable performance measurements that compare this driver with OpenTabletDriver 0.6.7 on the same machine ([performance](PERFORMANCE.md)); driver behavior is unchanged. Release 0.7.7 adds differential tests against OpenTabletDriver 0.6.7's own pipeline and property tests for malformed input and settings ([behavior contracts](parity/BEHAVIOR_CONTRACTS.md#differential-tests)); driver behavior is unchanged. Release 0.7.8 embeds OpenTabletDriver 0.6.7's tablet configuration database, loads it at startup with the user's override files and adds the `tablets` command ([tablet configurations](parity/BEHAVIOR_CONTRACTS.md#tablet-configurations)); device selection and pen handling are unchanged. Release 0.7.9 excludes ignored and wrong-platform .NET filter classes from discovery and rejects them with a specific error if enabled explicitly. Release 0.7.10 adds a metadata-only [plugin corpus](parity/PLUGIN_CORPUS.md), a pure endpoint matcher for future device integration, and OpenTabletDriver-compatible missing/null .NET filter setting defaults. The matcher is not wired into HID device selection.

Release 0.7.11 adds direct and inherited managed TabletReference field/property injection, checks two catalog archive hashes and their assembly metadata, and matches the pinned XP-Pen negative-lookahead device string in the pure endpoint matcher. Release 0.7.12 keeps saved null .NET settings editable as typed plugin property rows, passes the pinned PTH-660 configuration to managed TabletReference injection at plugin load, and verifies two more catalog archive hashes and assembly metadata: Windows Ink and Temporal Resampler. The archive audit does not establish runtime compatibility. The table below records implemented behavior, not roadmap completion.

Suggested next increments are additional managed-plugin services and settings controls, connecting endpoint matching to safe device selection, native pen output, and control-plane work. Pen side buttons remain in B02 of the full-parity backlog but are deferred by owner priority; B01 shared action ownership can still proceed when another task needs it. Each increment needs upstream source references, replay/error tests, and device validation where hardware behavior matters. Preserve fixed-size report/state structures, reuse buffers, avoid report queues and hot-path allocation, and measure CPU work separately from device and OS latency.

Release 0.7.13 adds Filters editor Move up / Move down and Defaults controls (U04). Reordering stays within the built-in and DLL groups, with DLL execution still respecting pipeline stages. Defaults resets only the selected built-in or inspected .NET filter's settings and preserves identity and enabled state. Missing metadata and native DLLs do not receive guessed defaults. This changes editor behavior only; the input pipeline is unchanged. Focused model checks cover ordering through TOML save/load and reset behavior. Interactive UI and pen validation remain open; no panel or driver was launched during development. Defaults follow the pinned [PluginSettingStore](https://github.com/OpenTabletDriver/OpenTabletDriver/blob/736003ed72c8bbb28033b039d5a0bb76c344145c/OpenTabletDriver.Desktop/Reflection/PluginSettingStore.cs) attribute/constructor behavior; the buttons are a Rust editor workflow, not a claim of complete upstream UI parity.

Release 0.7.14 extends the plugin editor in five increments (partial U04/P02):

1. Show all declared .NET properties, preserving omitted settings separately from explicit null without constructing a plugin to obtain defaults.
2. Offer boolean and named enum choices, with text editing for flags.
3. Validate supported scalar edits against their declared CLR type and numeric bounds, including exact signed/unsigned integer limits and finite float values. Decimal edits use the raw JSON editor; custom types receive JSON syntax checks rather than plugin-specific validation.
4. Add **Use default** for one property, writing explicit null so the bridge uses `DefaultPropertyValue` or retains constructor behavior, while preserving the filter's identity and enabled state.
5. Switch between **Properties** and **Raw JSON** while retaining unknown keys and structured values; invalid edits block switching. Native DLLs and unavailable metadata retain the raw editor.

Long property lists use Previous/Next pages; hidden fields keep their edits. Invalid values also block Save/Apply until corrected, with the last valid profile retained. Read-only metadata properties cannot be changed through typed controls. The Rust compile check, workspace release build and managed bridge/package build passed on Windows.

The default rules follow the pinned [PluginSettingStore](https://github.com/OpenTabletDriver/OpenTabletDriver/blob/736003ed72c8bbb28033b039d5a0bb76c344145c/OpenTabletDriver.Desktop/Reflection/PluginSettingStore.cs); [GeneratedControls](https://github.com/OpenTabletDriver/OpenTabletDriver/blob/736003ed72c8bbb28033b039d5a0bb76c344145c/OpenTabletDriver.UX/Controls/GeneratedControls.cs) is the reference for attribute-driven controls. Enum choices and the raw JSON switch are Rust editor workflows, not evidence of full upstream UI parity. Dynamic validation providers, actions and broader managed-plugin services remain open. No local tests, plugin integration runs, interactive UI checks or hardware validation were performed for this increment; the panel and driver were not launched. Hosted CI remains separate.
