The original Desktop 0.6.7 assembly and its complete runtime dependency closure provide unchanged managed preset bindings, real driver/configuration/parser/device metadata and asynchronous daemon services. Release 0.16.10 runs the Linux and macOS report loop at real-time priority while a session drives output: `SCHED_FIFO` priority 40 on Linux, within the user's `RLIMIT_RTPRIO` unless the driver has `CAP_SYS_NICE`, and the time-constraint policy upstream's pull request 5071 uses on macOS. `OTD_RUST_REALTIME=0` keeps normal scheduling. In an offline Linux benchmark of the driver's hidraw reader and session loop, with every CPU busy, 44–65 % of reports were output more than 1 ms late at normal priority and none at real-time priority. Windows keeps its existing scheduling by default. The Experimental tab adds an optional MMCSS Pro Audio setting that takes effect at the next tablet-input start ([real-time scheduling](REALTIME_SCHEDULING_2026-10-05.md)). Failed registration retains time-critical scheduling. Native macOS execution, the extended Windows benchmark, and live input validation remain outstanding.

Release 0.16.9 runs the built-in Radial Follow in place of a tablet-space Radial Follow DLL entry in the filter list, as OpenTabletDriver orders filters. Until now it always ran before every DLL filter. With a pre-transform filter such as Temporal Resampler listed before the DLL, that changed how the same settings felt. Run alone, the built-in filter and the unchanged DLL produce the same positions. The Filters tab lists the built-in entry where it runs, and each session logs the filter order and settings ([comparison](RADIAL_FOLLOW_ORDER_2026-10-05.md)). The .NET bridge now tests each report type's interfaces once and compiles its report path when a session starts. In offline Linux runs, one report through the bridge took about 28 % less time and the first report under 1 ms instead of about 7 ms. Relative mode no longer calls `fmod` per report ([performance audit](PERFORMANCE_AUDIT_2026-10-05.md)). Windows tests, live input and hardware validation were not run.

Release 0.16.4 fixes catalog plugin and update downloads that failed with only `download failed: <url>` while the catalog loaded. GitHub serves release files from a different host than the catalog, and `curl.exe`, unlike upstream's .NET HttpClient, ignored the Windows proxy settings and failed when a certificate revocation list was unreachable. Release 0.7.14 extends the plugin editor in five increments (partial U04/P02):

1. Show all declared .NET properties, preserving omitted settings separately from explicit null without constructing a plugin to obtain defaults.
2. Offer boolean and named enum choices, with text editing for flags.
3. Validate supported scalar edits against their declared CLR type and numeric bounds, including exact signed/unsigned integer limits and finite float values. Decimal edits use the raw JSON editor; custom types receive JSON syntax checks rather than plugin-specific validation.

Release 0.8.0 advances several foundations without completing a parity gate:

- **D02:** Windows HID descriptors, indexed strings and attributes feed the database matcher. Physical pairing identifies the matching auxiliary collection, while the pen runtime rejects parser/specification changes it cannot execute. Initialization follows the selected strings, delayed feature reports and output reports. Failed or partial initialization aborts that session instead of upstream's warning-and-continue behavior. Synchronous HID string/feature calls cannot be interrupted in flight; cancellation is checked between them.
- **C01/C02:** Versioned native profiles preserve the complete source OTD document and unsupported native fields, retain missing/null distinctions, and diagnose unsupported active stores. New imports honor disabled Radial Follow entries; previously saved native entries retain their behavior. Profile collections, import previews and export reconciliation preserve other profiles and unknown stores. CLI integration is described in the README; other tablet profiles can be stored without gaining runtime device support. The GUI can save off-device profiles; runtime tablet/display requirements are checked before an existing worker is stopped. Failed temporary-file creation never deletes a pre-existing file.
- **D03/D04/P03:** Bounded native report values cover more report capabilities, and an IntuosV2 auxiliary decoder is available without opening an auxiliary endpoint or producing bindings. Stateful IntuosV2 touch and explicit Wacom-driver-prefixed decoders retain contact snapshots without enabling live touch output. Managed filters receive independently owned pen/raw/button data, tilt and supported proximity interfaces. This intentionally allocates managed objects per filter/report to preserve retained references; no current performance or unchanged-plugin integration result is claimed. At 0.8.0 output was restricted to one positional result; 0.9.0 replaces that managed dispatch contract below.
- **B01:** Fixed-capacity shared action ownership and a single-event Windows adapter separate desired holds from acknowledged output, with retryable cleanup and portable USB keyboard usages. They are foundations for the binding engine; broad key/button workflows and their live integration remain open.
- **S01/S02:** An optional headless daemon exposes versioned local `status`, `start`, `stop` and `shutdown` commands. A worker owns devices independently of CLI clients. The control pipe limits messages and snapshots and restricts access to the current user and SYSTEM. At 0.8.0 the GUI remained in-process; 0.9.0 attachment is described below. Running means the worker is active, including waiting for a tablet; shutdown acceptance precedes completion of worker cleanup.

No tests or hardware/UI/plugin runs were performed locally for this increment. `cargo check --locked --workspace --all-targets` and `cargo clippy --locked --workspace --all-targets -- -D warnings` passed during integration; these are compilation/static checks, not executed tests. Final package results are recorded separately. Earlier evidence does not validate the new paths. These historical checks do not establish current graph, UI attachment or storage behavior.


Release 0.9.0 advances five slices, without completing a full-parity gate:

- **S01/S02:** The panel attaches/reconnects through bounded background IPC to a persistent daemon and fetches its active configuration. Closing the panel leaves input running. Explicit Stop stops input; CLI shutdown stops the service after cleanup. Start can launch without a console window; guarded restart validates before stopping and rejects stale client identities. Protocol v2 refuses automatic launch alongside an older v1 service. Active-profile retrieval and guarded restart are also exposed through CLI `configuration`/`restart`.

Save As/recovery create new files. Portable directory selection and relative plugin relocation share core helpers. At 0.9.0, JSON previews did not apply settings or establish device support; the graphical converter follows in 0.10.0 below.

Failed dispatch never replays an accepted prefix and requests held-output cleanup. Async remains rejected; B01 is not yet the general binding engine. Stale duplicate relative reports after timeout now suppress the whole graph/contact path, matching the upstream Read gate; immediate origin/carry reset on physical loss remains intentional.

Release 0.13.0 adds these slices:

- **D05 (first slice):** every connected supported tablet runs at once. The tablet the panel's settings are for keeps the existing worker; each other tablet gets a companion session on its own thread with its OpenTabletDriver profile, or its full area when there is none. Companions stop and start with the driver and are rescanned on device changes. Only one tablet was connected during testing, so two tablets at once has not been run.
- **P05 (partial):** unchanged OpenTabletDriver `ITool` plugins are constructed with their settings, `OnDependencyLoad` and `Initialize`, and disposed when the driver stops; a tool that fails to start is logged and skipped, as upstream does. A fixture tool passes this lifecycle in CI and in a live daemon run with the PTH-660. No catalog tool has been tried. The plugin manager and `plugins install-file` install local zip/DLL files.
- **X02/X03 (historical experimental slice, superseded by 0.15.0):** `crates/otd-linux` runs one tablet through the portable core with hidraw input, report lengths from the report descriptor, USB strings through usbfs, and a uinput pointer. It is compiled and unit-tested only; it has never run on Linux hardware. WinUsage matching is now Windows-only and OTD settings import looks in each platform's upstream directory. CI builds the Linux binary and tests the portable crates on macOS.
- **P03/P05:** .NET filters run on every supported tablet. The decoder supplies each parser's pen buttons, and the graph no longer rejects report IDs other than IntuosV2's. A fixture filter passes this on an XP-Pen report.
- **P05:** timer-driven filters (upstream `AsyncPositionedPipelineElement`, such as interpolators) run. As upstream's PluginManager does, the bridge injects an `ITimer` into `[Resolved]` members before settings. The session fires due timers on the report thread between reads, and their emissions continue downstream of the emitting filter. Waits shorter than 50 ms use a high-resolution waitable timer; sessions without timer-driven filters keep their one-second wait. A fixture filter emits at 1000 Hz in CI. In a live daemon run with the PTH-660 it ran without errors at about 0.3% of one core. No catalog interpolator has been tried.
- **U04:** the plugin editor reads `[PropertyValidated]` choices as dropdowns, shows `[SliderProperty]` ranges and `[BooleanProperty]` descriptions as tool tips, and saves slider defaults when a filter is added, as upstream's GeneratedControls does. Reading validated choices runs the plugin's static member, as upstream does.
- **U05/S05:** Tablets > **Device string reader** shows strings 1-10 of each connected tablet. Help > **Export diagnostics** saves or copies the redacted diagnostic bundle.

Report processing is otherwise unchanged.

Release 0.12.0 adds the panel features OpenTabletDriver users expect:
- a tablet debugger, also available as the `debug` command;
- per-tablet settings, with the area editor and thresholds sized for the chosen tablet;
- a plugin manager for OpenTabletDriver's online plugin catalog, with SHA-256 verification;
- updates from GitHub releases, with checksum verification and rollback;
- named presets in the File menu, opt-in start with Windows in the tray, and a log export;
- `device-strings`, which reads a tablet's USB strings.

Report processing is unchanged, apart from one atomic load per report for the debugger.

Release 0.11.0 runs every tablet in OpenTabletDriver's database whose parser has a Rust port, which is all 52 referenced parsers. It adds the remaining 27 parsers (the Wacom Intuos, IntuosV1, Intuos3/4/Pro, Cintiq, Graphire, PL, PTU and 64-byte aux families, the Wacom-driver variants, the XP-Pen Deco 03, Acepen, Bosto, FlooGoo, Genius, Lifetec, RobotPen, ViewSonic, XENX and XenceLabs). Mapping, relative output, Radial Follow and thresholds take the selected tablet's size and ranges from its configuration. A new fixture, decoded by OpenTabletDriver's own parser classes, checks every parser on 10,400 seeded packets. Only the PTH-660 has been tested on hardware; buttons, wheels and touch on other tablets are decoded but not bound. See [other tablets](parity/BEHAVIOR_CONTRACTS.md#other-tablets).

Release 0.10.0 advances five bounded slices; all parity gates remain open:

- **D06-D08:** 23 additional stateless parser dispatchers cover IntuosV3, three Bamboo variants, five UCLogic/Huion tilt variants, seven other Huion/XP-Pen variants and seven generic/Veikk variants. The registry marks 25 type names Partial including earlier IntuosV2/prefixed-touch coverage. Raw-only unknown packets, absent capabilities and explicit range-loss events remain distinct. Live detection/execution still accepts only supported PTH-660 configurations.
- **S04/D03-D08:** The offline `decode` command exposes 27 names, with 192-byte packets, at most 4,096 reports and 4 MiB input. JSON preserves transport bytes, parser-view bytes and report kind; touch state lasts for one invocation. See [offline report decoding](OFFLINE_REPORT_DECODING.md). No device/plugin/output path is started.
- **C05/U03:** The native [area conversion dialog](AREA_CONVERSIONS.md#graphical-conversion) shares CLI formulas, labels input units/quirks, and requires a valid preview. Acceptance changes only the unsaved tablet area, bypasses locks explicitly, and guards against profile changes while open. Cancel/failure preserves the profile; Save/Apply are separate user actions.
- **C04/S04:** [Named presets](NAMED_PRESETS.md) add offline list/show/save/export under the selected data directory. New names are the default; explicit replacement uses a captured-byte snapshot, revision increment and backup. Unsafe names/case aliases are rejected, and export cannot create files inside the preset directory. GUI selection, preset bindings and automatic runtime activation are not implemented.
- **C03/S02:** [Runtime replacement](RUNTIME_RECONFIGURATION.md) prepares plugin/HID resources on a candidate thread while old input continues, drains the old reader/output, then initializes and constructs the replacement before its first-read gate. Run commits the new generation. Pre-commit activation failure drains the candidate before resuming the retained old worker; Stop/Shutdown cancel all roles before readiness is processed. Trusted callbacks, hardware side effects and synchronous HID calls limit rollback/cancellation; this is partial C03, not full upstream transactional parity.

Rust formatting and strict `cargo clippy --locked --workspace --all-targets -- -D warnings` passed for the integrated code. No local tests, decoder/preset command runs, driver/daemon/UI launches, plugin execution or hardware validation were performed. Packaging is pending; final package/build results belong to the release notes. Historical evidence does not validate these new paths, and ledger evidence/gate states have not been promoted.
