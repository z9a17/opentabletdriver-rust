# Windows command-line source coverage (S04)

Claim: S04/C05 and Windows U01-U06 continuation, branch `parity/desktop-completion`, base `632a37d` (v0.17.1). This replaces the older matrix of offline aliases. Ownership is Windows CLI/panel source; the parent owns daemon/protocol integration and package compilation.

Baseline: [Console commands](https://github.com/OpenTabletDriver/OpenTabletDriver/blob/736003ed72c8bbb28033b039d5a0bb76c344145c/OpenTabletDriver.Console/Program.Commands.cs), [command registration](https://github.com/OpenTabletDriver/OpenTabletDriver/blob/736003ed72c8bbb28033b039d5a0bb76c344145c/OpenTabletDriver.Console/Program.cs), and [profile/store helpers](https://github.com/OpenTabletDriver/OpenTabletDriver/blob/736003ed72c8bbb28033b039d5a0bb76c344145c/OpenTabletDriver.Console/Program.Misc.cs), pinned OTD 0.6.7.

The original names now use one persistent daemon-owned Console connection. It is available on the native daemon without enabling the public upstream listener. GetSettings and the resulting SetSettings share revision/device guards. No console command silently launches a daemon. Native TOML file operations remain `profiles`, `devices`, `presets`, `native-save`, `native-save-defaults` and `native-stdio`; explicit `load FILE.toml` and `save FILE.toml` retain their native behavior. Original binding indices are zero-based; native profile file setters retain their existing one-based indices.

| Original command | Windows implementation |
| --- | --- |
| `load FILE`, `save FILE`, `save-defaults` | Original JSON collection load/apply and coherent collection save. Explicit replacement uses exact-byte snapshots, sidecar ownership, atomic publication and backup. Default save invokes the collection owner so its saved-file snapshot stays current. |
| `preset NAME`, `savepreset NAME`, `listpresets` | Original `.json` collections in the daemon's actual PresetDirectory; native `.toml` presets share the folder without being selected by these commands. Saving a preset never replaces an existing file. |
| `detect` | DetectTablets followed by GetSettings/SetSettings; does not replace daemon ownership with a restart alias. |
| `installplugin PATH`, `uninstallplugin FOLDER`, `listplugins` | Actual daemon installation/removal; folder inventory is rooted in its actual PluginDirectory. Uninstall names cannot traverse directories. |
| `getstring VID PID INDEX` | Actual RequestDeviceString on that daemon. |
| `setoutputmode TABLET PATH` | Actual original output PluginSettingStore constructed by the daemon registry. |
| `enabletabletfilters`, `disabletabletfilters`, `resettabletfilters` | Existing first-path enable, disable every matching entry, or remove every matching entry then append constructor-default stores, exactly in requested order. |
| `enabletools`, `disabletools` | Actual global Tools collection, retaining existing settings when enabling and disabling all matching paths. New stores use actual constructor defaults. |
| `setdisplayarea`, `settabletarea` | Centered pixel/mm dimensions and coordinates; optional tablet rotation defaults to zero. |
| `maptodisplayindex` | Index matches `listdisplays`, including the virtual screen; uses actual desktop positions and upstream virtual-screen centering. |
| `setsensitivity`, `setresettime` | Relative X/Y sensitivity, optional rotation and TimeSpan reset delay in milliseconds. |
| `settipbinding`, `setpenbinding`, `setauxbinding` | Real registry/friendly-name binding stores, tip threshold and zero-based pen/aux slots. Native toggle/preset and original managed bindings are no longer described as absent. |
| `setenableclipping`, `setenablearealimiting`, `setlockaspectratio` | Live original absolute-mode fields; retains unrelated document properties. |
| `log`, `getallsettings`, `getoutputmode`, `getareas`, `getsensitivity`, `getbindings`, `getmiscsettings`, `getfilters`, `gettools` | Original collection getters and configured store/property formatting; per-profile getters take TABLET, matching upstream. `getallsettingsjson` additionally exposes the unchanged collection JSON. |
| `hasupdate`, `installupdate` | Actual daemon CheckForUpdates/InstallUpdate; an absent update does not install. |
| `listoutputmodes`, `listfilters`, `listtools`, `listbindings` | Registry types and friendly names, including installed managed classes; no native-only syntax inventory presented as the original class list. |
| `listdisplays` | Actual physical display inventory followed by virtual screen, matching setter indices. |
| `getdiagnostics` | Prints the daemon diagnostic result. Native `diagnostics --output FILE` remains the separate redacted bundle writer. |
| `stdio` | Bounded quoted text-command loop with a retained connection; errors do not dispatch partial oversized commands. Native protocol JSON lines remain `native-stdio`. |
| `edit` | Opens EDITOR on a unique original JSON copy in the daemon's dedicated temporary directory, compares actual bytes, applies only a changed valid document, and removes the temporary copy. Metadata heartbeats keep the original revision guard while editing; a changed daemon/settings generation is rejected. |

Transport errors never blindly replay mutations: they report an uncertain outcome and require an explicit later read. A following stdio line may reconnect as a new request. Collection edits preserve unknown fields, disconnected rows and store ordering. Native settings that have no exact original-format representation remain explicit service errors rather than being silently discarded. Active collection apply retains the existing guarded per-device transaction and rollback; it is not an atomic multi-device commit. Logs, command lines and RPC responses retain their documented bounds. EDITOR argument quoting is parsed without shell expansion or command substitution.

Integration dependencies: the parent adds the always-available private Console listener, same-user/PID-checked pipe helper, and setup-only `GetPluginTypes`/`ConstructPluginStore` service extensions. The latter must construct real original stores rather than substitute attribute-only defaults. This source delivery does not claim executed plugin constructor or original-client compatibility.

No tests, formatting, Clippy, check suites, builds, CLI runtime, UI, driver, daemon, plugins, hardware or live input were executed by this source worker. Parent-owned actual distribution compilation is separate; hardware and original-client qualification remain unverified. Linux/macOS console workflows are a separate agent's scope.

Windows desktop workflow source now includes original collection Load/Apply/Reset/Save Default/Save As, JSON and TOML presets in both the File and notification-area menus, explicit preset refresh, the six-page setup guide, full device-string reading/dumping, and typed registered managed output/binding settings. Collection mutations use the daemon-owned Console connection; native profile Save/Apply keep their separate per-device destination. Preset confirmation/file-dialog completions check the original panel identity, editor revision, selection generation and operation ownership before changing a draft or writing it. Registered-type selection explicitly reloads installed metadata, so the plugin manager's installation/removal does not leave a cached selector stale.

The pinned [tray workflow](https://github.com/OpenTabletDriver/OpenTabletDriver/blob/736003ed72c8bbb28033b039d5a0bb76c344145c/OpenTabletDriver.UX/TrayIcon.cs) uses the same preset selection handler as the main window. The native tray follows that ownership route and pages large inventories without truncating the available presets. These are source implementation statements; desktop interaction, theme/DPI behavior, plugin execution, hardware input and command integration were not run during this task.

Original collection Load/preset/Reset does not depend on finding a model the native editor can project: the full document still reaches the guarded daemon transaction, and an unavailable projection leaves the existing native draft with an explicit message. Help also provides original daemon diagnostics to a new file or the clipboard through `GetDiagnosticInfo`, alongside the separately labeled redacted native exports. The original export includes environment variables and console logs.

Both native Windows updater entry points now reserve the existing daemon's tablet sessions and global tools before file replacement. They wait for real drain completion, retain installation plus cleanup errors, and wait for the actual pre-update tool configuration to finish restoring on cancellation. Check-only works offline; installation requires the existing daemon and never launches it implicitly. The Console updater uses the same daemon reservation; archive/journal recovery remains separate from the resource ownership receipt.
