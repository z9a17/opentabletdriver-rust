# Performance and usability audit: 0.14.1

This audit reviewed the production Rust core, Windows runtime and control panel, managed compatibility bridge, experimental Linux runtime, persistence, plugin installation and release paths. The source baseline was `fa50285c9be9d29d5c57599d427366e36fcc2b1d` (0.14.0). Upstream comparisons use OpenTabletDriver 0.6.7, `736003ed72c8bbb28033b039d5a0bb76c344145c`. The changes address concrete source defects and configuration friction; they do not establish full OpenTabletDriver parity.

The entire task stayed in the background. No panel, driver, daemon, HID session, live plugin, input injection or original-driver process control was started. The project instructions disable CI and the pre-release format/Clippy/test/build check suite. Source reviews and release-asset compilation are recorded separately below. No latency benchmark, allocation counter, visual check or physical tablet validation was run. Earlier releases' measurements remain historical evidence.

## Report processing and latency

| Source finding | Change | Evidence boundary |
| --- | --- | --- |
| `decoders::TabletDecoder::Values` reduced full parser reports to `PenReport`, discarded tool/mouse/aux/wheel/touch fields and rounded coordinates/tilt. The pipeline also invented absent tilt/eraser interfaces. | Runtime dispatch carries the original inline `ReportEnvelope`. Managed snapshots implement the actual parser interface sets. The specialized IntuosV2 decoder remains. | Rust values stay inline and Raw stays borrowed. The larger enum can affect stack/code generation; no timing or allocation measurement was performed. |
| Newly preserved mouse reports have no pen pressure and could inherit held tip contact from a preceding pen report. | Native contact is released on a mouse report without pressure. Plugins still see absent pressure. Nonpositional metadata does not replay pointer output. | Mouse buttons/scroll and auxiliary bindings are not newly implemented. |
| Managed graph gates rejected every packet larger than 192 bytes, including configured 361/1101-byte endpoints. Debug capture stopped at 512 bytes and offline decode at 192. | Graph transport, debugger capture and offline decode retain complete packets up to the u16 HID length limit. Hex decoding reserves according to actual input size. | The legacy position-only managed adapter retains its PTH-specific bounds. Full hardware operation on those larger endpoints is unverified. |
| `session::run` reused a zero timer deadline after firing its tick. Windows then armed an unnecessary immediate high-resolution wait. | Re-read the next deadline after one tick; zero waits poll input/stop directly. | The one-tick-before-input rule remains. No physical or numerical latency improvement is claimed. |
| `SessionTimer` accepted invalid intervals and overflowed deadline/microsecond arithmetic. | Validate finite positive intervals, cache period ticks, saturate deadline additions and convert long delays without multiplication overflow. | Invalid plugin settings now fail clearly instead of creating a tiny/busy timer. The 0.05 ms minimum remains. |
| Display snapshot failures left the old absolute mapping/contact active. | Pause mapping and release output. Retry a failed snapshot separately from an unchanged invalid mapping, avoiding repeated mapper rebuilds/logs during report flow; recover even when the valid snapshot equals the previous one. | Cleanup retries remain mandatory. No monitor-change test was performed. |
| Shared absolute-position dedup stripped MOVE from a real contact transition; a physical mouse movement could relocate the subsequent tablet click. | Retain MOVE on actual global button transitions. | Stationary hover dedup remains: another mouse can move the cursor until tablet movement/contact produces output. |
| Mouse `SendInput` failure could report stale last-error text or success. | Clear last error first and provide an explicit zero-return fallback. | Successful output remains allocation-free by source inspection; OS input was not exercised. |

The successful core native path still uses inline state, borrowed packets, cached transforms and direct callbacks. Rust-only profiles do not initialize CoreCLR. The shared-output mutex remains held through acknowledgement because multi-tablet button ownership and position commits must be serialized. Managed snapshots retain independent arrays because unchanged plugins can retain reports; pooling them would change behavior. Trusted native or managed callbacks can still allocate, block or fail.

The empty absolute pipeline computes a floating transform and an integer mapping. That extra work is a valid optimization candidate, but replacing the integer path with normalized float output changes rounding. It is deliberately retained pending a contract-preserving design and permitted measurements. Archive hashing now streams 64 KiB chunks through CNG instead of loading an entire package into memory; this reduces input-buffer size by construction, not by a measured latency result. The CNG hash object is released on both success and failure, following [Microsoft's BCryptCreateHash contract](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptcreatehash).

## Plugin configuration and control-panel cleanup

| Source finding | Change |
| --- | --- |
| The bridge rejected old saved keys even though upstream skips no-longer-declared properties. | Apply declared settings and preserve unknown saved JSON for rollback. Applies to filters and tools. |
| Plugin disposal exceptions skipped timer/context cleanup or hid the original construction error. Inspection also mapped installed managed DLLs into the panel until GC unload. | Host cleanup runs in `finally`; construction cleanup failures retain the setup exception. Inspection loads main and resolved managed dependency assemblies from streams, closing the files immediately. |
| Installing a package required a separate Add action; repeated Add duplicated configured filters. | Discover types in the background after install/update. Merge by canonical DLL path, kind and full type name; new entries are disabled. Keep existing settings, order and enabled state. |
| Defaults were hidden behind blank fields, and filter rows had no useful hover help. A stale tooltip list index could panic. | Show known attribute/editor defaults in help/reset controls and filter-row summaries; labels expose help too. Bound-check row lookups and verify tooltip notification identity. No constructor is run to guess unknown defaults. |
| Updates/removals left stale descriptors and inspection errors cached. Older worker completions could replace newer information. | Invalidate affected paths and revision-stamp inspections. Centralize metadata refresh/removal; retain visible unavailable state for missing types. Single-DLL addition preserves the chosen path while comparison canonicalizes aliases. |
| Metadata arriving while editing never refreshed the fallback editor afterward. | Defer rebuilding until editing ends and no invalid draft would be lost. |
| DateTime and TimeSpan fields required JSON quotation syntax. | Edit their literal string representations, matching upstream text controls. |
| Manager completion and preset menu creation synchronously scanned/parses files. | Worker completions supply installed-plugin snapshots; preset menus use cached names and a separate stable command-index snapshot. |
| Update restart blocked the window thread, ignored failed shutdown and spawned a replacement before resolving unsaved edits. | Resolve edits before restarting, freeze changes while the worker runs, require accepted shutdown and wait for the captured old process handle. A successful restart closes without a second discard prompt; failure keeps the editor. |
| Diagnostic export/copy queried a potentially slow daemon and wrote files on the window thread. | Generate/serialize the immutable profile snapshot and publish the export on a worker. Only final clipboard publication/logging runs on the UI thread. |
| Area painting deleted rotated fonts while they were still selected into the DC, leaking GDI handles. | `Canvas::text` and `text_at` restore the previous selected font before callers delete temporary fonts. |
| Very large raw packets caused full-string formatting/wrapping during debugger redraws. | Show a bounded raw preview with remaining-byte/trailing-zero counts while retaining full capture and background decoding. |
| A short/high-DPI slider could invert its channel and panic in `clamp`. Pen settings also claimed Ink was unavailable for pen profiles. | Guard empty/inverted slider ranges; derive the pen-settings capability note from the selected output mode. |

Installation now updates the editor by adding discovered supported types as disabled entries; Save/Apply is still required. The existing 32-entry bound remains. This does not activate a newly installed filter automatically.

Default semantics remain explicit. New entries receive known `[DefaultPropertyValue]` or float-slider editor defaults. An imported omitted property keeps its constructor value. Explicit null selects an attribute default only when that attribute exists. Constructor-only values remain unknown during inspection. Reset writes a known default when available; raw JSON remains available for exact omitted/null settings. The upstream Plugin API has no class-description attribute; hover uses available class/property information.

## Lifecycle, settings and recovery

| Source finding | Change |
| --- | --- |
| Rejected companion settings were swallowed and replaced with an active full-area default. | Distinguish absent profiles from rejected profiles; log/skip rejected tablets. |
| Disconnecting the primary tablet stopped healthy companions; a changed primary endpoint could briefly start with a companion profile. Optional discovery failure could also stop the primary. | Keep companions for the active generation and reserve/drain changed primary endpoints. Exclude the primary configuration while its old path is absent; distinguish benign discovery completion from supervisor errors. Apply, Stop and final shutdown still drain all companions. Rechecking stop after event reset avoids losing a wake and waiting for the discovery timeout. |
| Runtime validation/profile thresholds used only the built-in database. UI discovery/import could choose a different tablet than the runtime. | Resolve the effective custom-configuration database at setup and share connected-name discovery across CLI and UI workers. Database/specification failures propagate at setup instead of silently supplying PTH ranges. No configuration reads enter report processing. |
| Linux loaded a default profile before selecting the connected device and retried deterministic errors with repeated initialization writes. | Select first, load that tablet's saved settings, reject conflicting explicit identities, validate mapping/pipeline and create output before initialization. Normal disconnect/ENODEV and transient HID open/init/read failures reconnect. Invalid configuration, unsupported setup, output creation and unreleased output ownership stop with an error. |
| Profile/preset create-new sentinel locks remained after a crash. | Atomically publish an immutable marker and hold an OS file lock. Process death releases lock ownership. Never unlink a modern lock while writers can be active; held Windows markers also deny delete sharing. |
| Interrupted plugin promotion could leave its canonical DLL folder missing; inventory exposed stages/backups. A first recovery draft also blocked unrelated commands and erased inventory on lock errors. | Recover at plugin-loading/mutation boundaries under the installation mutex. Hide internal folders, isolate malformed backups, clean orphan stages and retire removed folders. Inventory is read-only, returns errors and keeps the prior panel snapshot on failure. Recovery I/O failure cannot prevent opening the panel to Stop. |
| Original-driver termination/restoration preserved only its executable path and lost launch options/context. | Check coexistence without terminating or relaunching the original driver. Remove the obsolete restoration machinery. |

**Changed startup behavior:** stop the original OpenTabletDriver through its own panel before starting Rust output. Rust now refuses to start alongside it and leaves its process/launch settings untouched. This is a startup check; an original driver started later is not detected. This audit did not act on the currently running driver.

**Lock migration and downgrade:** persistent modern `.lock` and `.presets.lock` files are intentional. Existing legacy pid-only sentinels are refused because they cannot prove an idle writer. Close every driver/panel/save process before removing a legacy lock once. Older binaries use create-new sentinels and cannot save through a modern marker; downgrade only after every writer has stopped, then remove the modern markers for the older writer. Do not remove them during an active modern save.

Companions still begin at the first committed primary activation; a cold start with a named absent primary can wait. While a primary path is absent, its configuration name is reserved conservatively, so another identical model can be temporarily excluded from companion startup. Configuration files changing between import and runtime setup are not an atomic configuration transaction. Single-preset load/save remains synchronous. Malformed plugin backups remain hidden and require repair before replacing that same plugin; unrelated commands continue. Managed inspection avoids file mappings for managed assemblies, but arbitrary static value providers/native dependencies have separate lifetime and blocking behavior. Update shutdown retains the existing unconditional protocol, so status-to-shutdown process replacement is not a fully guarded transaction. Recovery/inventory locks protect setup and promotion, not an entire future DLL-loading generation. A concurrent external installation can still cause a visible metadata inspection error cached until refresh/restart; requested filter loading fails visibly rather than silently dropping it. Optional companion discovery ending normally leaves the primary running but needs a generation restart to retry discovery. These limits are separate from the repaired paths.

## Review and release evidence

Audit coverage includes core reports/parsers, mapping/relative/smoothing/output/action ownership, native/managed plugin boundaries, HID lifecycle/companions, configuration/import/persistence, IPC/diagnostics/updater/catalog, control-panel drawing/editors/tray/startup and the experimental Linux input/output sources. Findings were traced through concrete callers and the pinned upstream interfaces. Source fixtures and existing test assertions were read or adjusted where contracts changed; they were not executed.

The [independent review decisions](audit/0.14.1/REVIEW.md), release notes and [decision trail](audit/0.14.1/decisions.tsv) record findings, retained tradeoffs, packaging results and artifact provenance. The owner performs release checks manually. Windows release assets are compiled for publication; that compilation is not the skipped pre-release verification suite. Linux source changes are not Linux runtime/build evidence. Full arbitrary asynchronous .NET plugins, broad bindings/auxiliary orchestration, native wheel/touch actions, macOS and physical latency remain open roadmap work.
