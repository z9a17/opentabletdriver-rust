# Plugin manager theme handoff

Edited only `src/ui/plugin_manager.rs` in `E:/AgentWork/projects/opentabletdriver-rust`.

The manager now uses the main application's current LOOK palette for its window, list background, selected rows, header, details field, status text and buttons. High contrast uses `Palette::selection_text()` for highlighted text. The buttons use the existing `draw::button` renderer and the same hot, pressed, disabled, focus and keyboard cue states as the main window.

Catalog rows are custom drawn to preserve the palette's selection colors. Their column bounds come from the native header and are mapped into list coordinates, so horizontal scrolling and column resizing retain alignment. Row text comes from the existing ListView items. The native control still owns selection, navigation and scrolling. Header custom drawing covers the entire header, including the blank area after its last column. A ListView subclass handles these notifications because the header sends them to the ListView rather than to the manager window. The subclass removes itself on destruction.

The layout adds bold Plugins and Plugin details labels, places status on its own full-width line and uses the main field border renderer around the list and details. The details edit keeps its native read-only/copy/scroll behavior and gets an inset formatting rectangle. A minimum size keeps the six existing action buttons visible.

The manager owns its fonts and DarkMode helper. DPI changes update all fonts and scale current column widths, preserving their relative user-adjusted sizes. `pub(super) fn apply_theme()` updates title bar, scrolling controls, header and explicit ListView colors, then invalidates all child controls. The root integrator must call this after updating LOOK in `App::apply_theme` so app menu theme choices and system/high-contrast changes reach an already open manager. The manager also handles native `WM_THEMECHANGED`.

The manager now belongs to the main panel through its native owner HWND, captured before window creation and outside the APP borrow. Separate thread-local Cells hold the manager HWND and shutdown/restart state, so close and update requests remain effective while a manager command holds its RefCell borrow inside a native modal dialog. Close requests disable the manager immediately and defer explicit destruction until the outer manager callback releases its borrow. Native owner destruction can also destroy the manager during that modal loop; WM_DESTROY clears the HWND immediately, WM_NCDESTROY releases available Manager state after native children have been destroyed, and the outer callback releases any state retained by its modal borrow. Fonts therefore remain alive for the native child lifetime. Commands and new work require both live windows and a panel that is neither closing nor awaiting restart. File-dialog and confirmation returns recheck that state before installing. After modal callbacks, restart disablement is reapplied because native dialogs can re-enable their owner. Theme refresh requests blocked by a modal borrow are also applied after the outer callback returns.

Source review checked the current windows-sys 0.61.2 declarations, callback signature, palette helpers, draw helpers, nested window-message borrow behavior and resulting diff. No tests, formatting, clippy, build checks or live UI validation were run. No UI, driver, daemon, hardware, plugins, input or active settings were opened or changed. The root integrator performs the release-asset compilation separately.

Manual release follow-up should check light, dark and Windows high contrast with the manager already open; selected rows with and without focus; header trailing space; horizontal scrolling and resized columns; disabled buttons; keyboard cues; and mixed-monitor DPI changes.
